# 문제 해결

먼저 실행한 명령·종료 코드·문제 단계와 `oni version`, `onidot-studio version`을 확인하세요. 로컬 점검은 `oni doctor`, 특정 MCP 연결의 실제 접속 점검은 `oni doctor --connection local` 또는 `--connection remote`입니다. 버전·경로·오류 코드만 공유하고 `instance.json`, 토큰 파일, 로컬 일회용 링크·setup-code·긴급 로그인 출력, DB 비밀번호는 공개하지 않습니다.

## 설치·기동이 안 될 때

| 증상 | 확인과 다음 행동 |
| --- | --- |
| `oni: command not found` | `~/.local/bin/oni version`을 실행합니다. 된다면 PATH에 `~/.local/bin`을 추가하고 새 셸에서 확인합니다. |
| 서버 파일·버전·경로 오류 | 같은 archive의 두 일반 파일을 같은 디렉터리에 설치합니다. doctor에서 설치 서버 경로·버전과 실행 중 서버 경로·버전을 비교합니다. 서버를 PATH의 다른 파일로 대체하거나 symlink로 연결하지 않습니다. |
| checksum 불일치·압축 해제 실패 | 설치하지 않습니다. 같은 릴리스의 archive·SHA256SUMS를 새 빈 다운로드 폴더에 다시 받고 검증합니다. |
| `이미 초기화` | 기존 인스턴스를 보존하고 `oni daemon start`로 진행합니다. init을 성공시키려고 설정·DB를 지우지 않습니다. |
| 포트 사용 중 | `lsof -nP -iTCP:18181 -sTCP:LISTEN`으로 점유 프로세스를 확인합니다. 무관한 프로세스를 강제 종료하지 않습니다. 기존 설정·데이터를 보존하고 사용할 빈 포트를 확인하세요. 로컬 로그인에 외부 callback 등록은 필요하지 않습니다. |
| `starting pid=…` | `oni daemon status`, 로컬 `/ready`, doctor가 표시한 state의 `server.log`를 확인합니다. 바로 성공으로 취급하지 않습니다. |
| 디렉터리 권한 오류 | 실제 config/data/state/runtime 경로는 현재 사용자 소유 `0700`, 설정 파일은 `0600`인지 확인합니다. 경로에 symlink·다른 사용자 쓰기 권한이 있으면 안전한 실제 경로로 옮길 계획부터 세웁니다. 재귀 chmod·chown을 임의로 실행하지 않습니다. |
| PID 신원을 확인할 수 없음 | 무관한 PID에 신호를 보내지 않는 보호 동작입니다. status와 로그를 확인하고 자신이 띄운 프로세스인지 식별한 뒤 복구합니다. `killall`·패턴 kill은 쓰지 않습니다. |
| 웹 대신 준비되지 않았다는 응답 | 웹 내장 출시 패키지인지 확인합니다. `/ready`만 통과해도 웹 자산이 정상이라는 뜻은 아닙니다. 같은 릴리스의 검증된 패키지로 교체합니다. |

## macOS에서 실행이 차단될 때

지원 CPU가 Apple Silicon인지, 공식 릴리스와 checksum이 일치하는지 먼저 확인합니다. 현재 후보 산출물은 서명·공증 완료를 보장하지 않습니다. macOS가 차단하면 사용자 본인이 시스템 설정의 개인정보 보호 및 보안에서 해당 실행 파일의 허용 여부를 판단하세요. 허용 항목이 없거나 조직 정책으로 막히면 관리자에게 문의합니다. 보호 기능 전체를 끄거나 알 수 없는 파일의 격리 속성을 일괄 제거하지 않습니다. OS별 허용 화면은 버전에 따라 다를 수 있습니다.

## 웹 로그인과 주인 복구

| 증상 | 확인과 다음 행동 |
| --- | --- |
| `oni open`이 데몬을 찾지 못함 | 같은 OS 사용자·설정 경로에서 `oni daemon start`, `oni daemon status`를 확인한 뒤 다시 실행합니다. open은 데몬을 스스로 시작하지 않습니다. |
| 로컬 링크 만료·이미 사용됨 | 링크는 2분·일회용입니다. `oni open`을 다시 실행하고 본인 브라우저에서 바로 엽니다. 복원 후에도 새 링크를 받습니다. |
| snap 등 브라우저가 runtime 파일을 열지 못함 | `oni open --direct` 또는 로컬 연결의 `oni login --connection local --direct`로 다시 시작합니다. `--print` 출력은 비밀이므로 본인이 직접 여는 경우만 사용합니다. |
| 비밀번호 로그인 429 | 계정·클라이언트 시도 예산을 초과했습니다. Retry-After와 화면 안내만큼 기다린 뒤 올바른 정보로 시도합니다. 복구 코드도 같은 계정 예산을 쓰므로 우회 수단으로 반복하지 않습니다. |
| `REAUTH_REQUIRED` | 계정 설정의 비밀번호·복구 코드·onidot 연결 등 민감 작업에는 15분 이내 인증이 필요합니다. 다시 로그인하고 해당 화면으로 돌아옵니다. |
| `LAST_METHOD` | 마지막 사용할 수 있는 수단을 삭제할 수 없습니다. 다른 수단을 먼저 등록하고 정책에서 허용한 뒤 삭제합니다. 복구 코드는 수단 수에 포함되지 않습니다. |
| 비밀번호·onidot 수단을 사용할 수 없음 | 셀프호스팅 공개 주소는 HTTPS와 유효한 인증서가 필요합니다. 비loopback HTTP에서는 해당 수단이 닫힙니다. 주인의 수단 정책과 계정 등록 상태를 확인합니다. |
| `/ready`는 200인데 onidot 로그인 503 | onidot 계정 로그인을 켠 경우에만 discovery·issuer 연결을 확인합니다. 비밀번호 로그인·로컬 일회용 링크의 외부 인증 준비 조건이 아닙니다. |
| onidot callback 불일치 | 선택 설정한 셀프호스팅 client에 `https://실제-도메인/auth/oidc/callback`을 정확히 등록합니다. scheme·host·port·path를 모두 맞춥니다. |
| setup-code 만료·거부 | 셀프호스팅 첫 주인용 24시간·일회용 코드입니다. 주인이 없을 때만 재발급하며, 이미 주인이 있으면 기존 계정으로 로그인합니다. |
| 다른 onidot 계정으로 로그인 거부·`IDENTITY_IN_USE` | 현재 인스턴스 계정에 연결한 onidot 신원을 사용합니다. 이메일만 같다고 자동 연결하지 않으며 다른 계정에 연결된 신원을 가져올 수 없습니다. |
| 초대·재설정 링크 만료·거부 | 발급한 주인에게 새 링크를 요청합니다. 재설정 링크는 24시간·일회용이며 재설정 뒤 기존 브라우저 세션은 종료됩니다. AI 연결·PAT는 자동으로 회수되지 않습니다. |
| 주인이 로그인 수단에 접근할 수 없음 | 셀프호스팅 서버에서 동일 환경으로 `onidot-studio emergency-login`을 실행합니다. 출력된 10분·일회용 링크를 직접 열고 확인합니다. 로컬은 `oni open`을 사용합니다. |
| CSRF/HTTPS 쿠키 문제 | 정해진 공개 주소로 접속하고 역프록시가 Host·scheme·경로를 보존하는지 확인합니다. callback만 별도 HTTP로 우회하지 않습니다. |

## AI 등록·MCP 연결이 안 될 때

```sh
oni connection list
oni doctor --connection local
```

연결 URL은 웹 홈이 아닌 MCP endpoint 전체입니다. `--resource`를 생략하면 같은 URL을 사용하며 서로 다른 값을 주면 거부됩니다. HTTPS를 사용하고 로컬만 loopback HTTP를 씁니다.

- `로그인하지 않았습니다`: `oni login --connection local`을 실행하고 사용자 동의를 완료하세요. doctor 종료 코드 1이 서버 프로세스 자체의 장애를 뜻하지는 않습니다.
- 동의 모드·저장 토큰이 다름: 해당 연결을 `oni login --connection local --logout`한 뒤 URL·모드를 확인하고 다시 로그인합니다. 다른 연결의 토큰을 복사하지 않습니다.
- `register`가 AI CLI를 찾지 못함: 사용할 클라이언트의 공식 설치를 완료한 뒤 같은 사용자·PATH에서 다시 실행합니다. oni는 클라이언트를 설치하지 않습니다.
- 같은 등록 이름 충돌: 클라이언트에서 해당 이름의 기존 대상과 사용 여부를 확인합니다. 다른 등록을 통째로 지우지 말고 별칭을 구분하거나 사용자가 해당 항목만 해제합니다.
- 등록 성공 뒤 도구가 안 보임: 새 대화를 열고 `onidot-local`이 선택·활성화되어 있는지 확인합니다. 등록 readback·MCP 프로토콜 성공·실제 AI 호출은 서로 다른 확인입니다.
- 커스텀 경로 경고: register가 기록하는 `oni mcp`에는 경로 옵션이 없습니다. AI 프로세스도 같은 `ONI_*_DIR`/XDG 환경을 받아야 합니다. 기본 HOME과 커스텀 config를 섞지 마세요.
- 원격 timeout·TLS 오류: 해당 기기에서 DNS·인증서·MCP 경로·역프록시 스트리밍을 확인합니다. TLS 검증을 끄거나 토큰을 URL에 넣지 않습니다.

## READ/WRITE나 인스턴스가 맞지 않을 때

`oni connection list`의 URL·mode, doctor의 서버 정체·mode·Space 목록을 차례로 대조합니다. READ에는 쓰기 도구가 보이지 않아야 하고 서버에 직접 요청해도 거부되어야 합니다. doctor는 목록을 확인하며 직접 쓰기 요청은 보내지 않습니다. 목록이 부분 조회라면 그 한계를 그대로 기록합니다.

기대와 다르면 해당 연결을 중단하고 웹의 연결된 앱에서 승인 Space·mode를 확인한 뒤 재인가하세요. 원하는 작업을 성공시키려고 READ를 WRITE로 바꾸거나 다른 서버에 저장하지 않습니다. 서버의 직접 쓰기 거부는 별도 검증 인스턴스에서만 확인합니다.

## 백업·복원·업데이트 문제

| 증상 | 확인과 다음 행동 |
| --- | --- |
| 백업 목적지가 이미 있음 | 덮어쓰지 않습니다. 존재하지 않는 새 경로를 지정합니다. |
| 백업 상위 폴더 없음·공간 부족 | 상위 폴더를 만들고 instance root 밖에 충분한 공간을 마련합니다. |
| 백업 중 daemon 응답 끊김 | status·로그·목적지의 COMPLETE를 확인합니다. 표식이 있어도 복원 검증 전 완료를 추정하지 않습니다. |
| 실행 중 복원 거부 | 자동 시작 서비스를 중지한 뒤 `oni daemon stop`을 실행하고 복원합니다. 같은 DB를 두 서버가 열게 하지 않습니다. |
| 미래/이전/migration 불일치 백업 | 백업에 맞는 원래 패키지·설정을 확보합니다. 검증되지 않은 버전으로 강제 복원하거나 DB 이력을 고치지 않습니다. |
| `RESTORED` 등 미활성 root 거부 | 중단된 동일 백업·동일 target의 restore를 다시 실행해 인증 폐기·설정 전환을 완료합니다. marker나 instance.json을 손으로 조작하지 않습니다. |
| `restore.lock` 파일이 남음 | 정상 영속 잠금 파일은 남아도 됩니다. 점유와 존재는 다릅니다. 지우지 말고 오류의 권한·점유 안내를 따릅니다. |
| 복원 뒤 세션/PAT/MCP 거부 | 로컬 복원의 의도한 동작입니다. `oni open`으로 기존 주인 로그인, 문서·첨부 확인, oni login 재인가, 새 PAT 발급을 수행합니다. |
| 업데이트 실패 | 이전 두 바이너리·업데이트 전 백업·설정 사본으로 복구합니다. migration된 DB를 이전 바이너리로 바로 열지 않습니다. |

PostgreSQL의 백업·복원은 로컬 명령과 다릅니다. [셀프호스팅 복구](self-hosted.md#6-백업과-복구)의 중지·DB·첨부·설정 보존 절차를 확인하세요. 지원 요청에는 비밀 원문 대신 버전·OS·단계·오류 코드·백업 완료 여부·복원 target의 구분만 남기세요.

## 알려진 제한

- **OS 확인 범위:** macOS 26.5.1 Apple Silicon 실기와 Linux ARM64 컨테이너·AMD64 Rosetta 에뮬레이션의 설치·웹·MCP·복원 흐름을 확인했습니다. Linux 실기, systemd user 자동 시작, 다른 지원 macOS 메이저, 로그아웃·로그인/재부팅 지속성은 미확인입니다. 실제 QEMU 실행도 미확인입니다. Rosetta에서는 종료 경합 스트레스 시험이 해석기 assertion으로 중단된 이력이 있으며, 기능 E2E 통과가 모든 에뮬레이션 동작의 보장은 아닙니다.
- **Windows·Intel Mac:** 현재 지원하지 않습니다.
- **8GB 기기와 성능:** 최소 메모리 목표는 8GB지만 실측은 RAM 48GiB 개발 기기에서 수행했습니다. 8GB 실기·OS 파일 캐시를 비운 cold 검색·동시 요청/대형 첨부 부하의 자원 상한은 미검증입니다. [측정 조건과 수치](README.md#확인한-환경과-성능)를 함께 확인하세요.
- **백업 일정:** 자동 백업 일정과 보존 정책은 없습니다. 수동 `oni backup`으로 백업하고 별도 보관·복원 확인을 수행하세요. 이 명령은 로컬 SQLite 전용이며 셀프호스팅 PostgreSQL은 별도 [백업 절차](self-hosted.md#6-백업과-복구)를 따릅니다.
- **쿠키 포트 격리:** 브라우저 쿠키는 포트로 격리되지 않습니다. 서로 다른 인스턴스의 쿠키 이름은 구분하지만 같은 호스트의 다른 포트에도 쿠키가 전송될 수 있습니다. 포트만 달리하면 세션이 격리된다고 가정하지 말고, 신뢰 경계가 다르면 브라우저 프로필도 분리하세요.
- **macOS 실행 경로:** `./onidot-studio local daemon run` 같은 상대경로 전경 실행은 신원 확인 단계에서 거부됩니다. 같은 디렉터리에 설치한 두 명령을 PATH 또는 설치한 절대경로로 실행하고, 로컬 시작에는 `oni daemon start`를 사용하세요.
- **다운로드와 서명:** 검증한 설치는 터미널 기준입니다. 브라우저 다운로드의 Gatekeeper 흐름은 미검증이며 GUI 앱 서명·공증을 제공하는 배포가 아닙니다. SHA-256 일치는 서명·공증을 대신하지 않습니다.
- **로그인과 AI:** 로컬 로그인은 외부 인증 없이 일회용 링크를 사용하고, 셀프호스팅은 자체 비밀번호 계정으로 시작합니다. 선택한 onidot client 등록·실제 사용자 로그인과 MCP 프로토콜 시험·Claude Code/Codex 모델 대화 확인은 각각 별도 검증입니다. 각 연결에서 [실제 호출 확인](local.md#3-claude-codecodex-연결)을 마치세요.
- **복구 범위:** 검증한 것은 동일 후보 버전의 백업·새 root 복원·기존 인증 폐기·재인가입니다. 임의의 이전 버전 백업 업그레이드 경로는 보장하지 않습니다. 공간을 미리 확인하고, 실패한 복원·업데이트 뒤에도 기존 root와 백업을 보존하세요.
- **두 인스턴스 병행:** 자동 동기화·복제·장애 시 다른 인스턴스로 자동 저장은 없습니다. 저장할 인스턴스와 Space를 매번 구분하세요.
